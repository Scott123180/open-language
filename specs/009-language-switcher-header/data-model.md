# Data Model: Language Switcher in the Header

**Feature**: 009-language-switcher-header | **Date**: 2026-10-07

No database change. No new table, no new column, nothing new stored about the learner. The feature
adds one value to each language's data file and derives everything else from existing records.

## Language data file (changed)

`backend/app/language_data/languages/<code>.toml`, generated by the language kit.

| Field | Type | Rule | New? |
|---|---|---|---|
| `code`, `name`, `order`, `default_voice`, `voices`, `podcast` | as today | as today | — |
| `flag` | string | Required. Lowercase `flag-icons` name: ISO 3166-1 alpha-2 region, optionally `-subdivision` (`^[a-z]{2}(-[a-z0-9]+)?$`). Must be a flag the frontend ships (`FlagShipped`, research R2). | **yes** |

Values written by `kit.sh backfill` packs:

| Language | `flag` | Default voice |
|---|---|---|
| Spanish (`es`) | `es` | `es_ES-davefx-medium` |
| German (`de`) | `de` | `de_DE-thorsten-medium` |
| Italian (`it`) | `it` | `it_IT-paola-medium` |

The canonical file layout comes from the registry, so the kit decides where `flag` sits in the file.

## Records (changed)

- `LanguageRecord` (`app/language_data/records.py`) gains `flag: str`; the strict loader requires it
  and refuses a file without it.
- `PracticeLanguage` (`app/practice_languages/catalog.py`) gains `flag: str`, copied from the record.
- `language_kit.registry.REQUIREMENTS` gains `Requirement("flag", RUNTIME, AGENT, "009", …)`.
- `language_kit.context.RuleContext` gains `flag_codes: frozenset[str] | None`.

## Practised languages (new, derived)

```text
PractisedLanguages.codes() -> frozenset[str]
  = { conversation.target_language for every conversation (roleplay and podcast episode) }
  ∪ { code in PRACTICE_LANGUAGES where at least one flashcard deck has target_language = code }
```

Declared as a `Protocol` in `app/practice_languages/activity.py` and exported from the package root;
implemented in `app/services/factory.py` from `StorageProvider` and `FlashcardStorageProvider`
(research R3). Nothing is stored; a language joins the set as soon as its first conversation or
deck is created (FR-012), and leaves it only if all of them are deleted.

## Practice language option (API, changed)

`PracticeLanguageResponse` / frontend `PracticeLanguageOption` gain two fields (see
[contracts/api.md](contracts/api.md)):

| Field | Type | Meaning |
|---|---|---|
| `flag` | string | The language's flag name, for `LanguageFlag` |
| `has_activity` | boolean | The language is in `PractisedLanguages.codes()` |

## Language groups (frontend, derived)

```text
groupLanguages(languages, currentId) -> { mine: Option[], others: Option[] }
  mine   = [current] + [l for l in languages if l.has_activity and l != current]   (catalogue order)
  others = [l for l in languages if not l.has_activity and l != current]           (catalogue order)
```

`languages` already arrives in catalogue order (`order` field). An unknown `currentId` puts nothing
first and groups the rest by `has_activity`. An empty group is not rendered (FR-011).
